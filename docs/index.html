02 / Workflow

Select a booking mode, then a state to see the backend rule and the frontend action.

EXPIRED → retry or manual assignment
No eligible worker or exhausted offers. Customer/admin can retry up to 3 times; an admin can assign an eligible worker with an audited reason.
Before work starts → CANCELLED
Customer/admin cancellation closes offers. Cancellation after IN_PROGRESS requires a future incident/refund policy.
03 / Financial contract

Fixed price is the default.

Welfare comes from surplus. With a zero surcharge, the current formula funds no welfare contribution.

Illustration only; this does not change the backend. Quote snapshots lock financial terms. Seeded INR 500 prices are demo values.

05 / Frontend team handoff

The backend is ready for wiring.

Build against server state and explicit unavailable states. Full screen-by-screen acceptance checklist →

Customer team

  • Use catalog UUIDs and server quotes.
  • Persist one idempotency key per booking attempt.
  • Render SEARCHING, EXPIRED and retry paths.
  • Reveal doorstep code only to its owner.
  • Label simulation and demo receipts visibly.

Worker team

  • Separate onboarding, pending and ACTIVE states.
  • Submit GPS with permission and freshness feedback.
  • Count down offers; handle a losing acceptance.
  • Enforce travel → arrive → OTP → start → complete.
  • Show gross, welfare and worker earnings distinctly.

Admin team

  • Verify declared skills and record evidence.
  • Filter society metrics without claiming tenant isolation.
  • Handle unfulfilled jobs with audited manual dispatch.
  • Refresh config after a stale-version conflict.
  • Show forecast unavailable when no model is connected.
Shared integration rules: coordinate refresh token rotation; poll /events with a cursor; refetch authoritative job data; handle empty 200 responses; render en/hi/ta; never log doorstep codes or full worker identifiers.
